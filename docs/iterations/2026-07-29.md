# Iteration 80: Operational Resilience (Market Calendar)

**Date:** 2026-07-29
**Theme:** Operational Resilience
**Tranche:** 8 (Slice 1)

## High-Level Summary
Implemented a `MarketCalendar` middleware for the Orchestrator to ensure the Live Agent does not run outside of US trading hours (09:30 - 16:00 ET) or on weekends. This represents a critical safety constraint for the live-trading architecture, preventing the agent from triggering erroneous massive rebalances based on stale weekend prices or wide after-hours bid/ask spreads.

## Details

### 1. Market Calendar Service
- Created `CalendarAdapter` interface to define `isOpen(timestampMs)`.
- Implemented `USMarketCalendar` which safely uses `Intl.DateTimeFormat` with `America/New_York` to compute the Eastern Time without brittle DST logic.
- Returns `true` only between Monday-Friday, 09:30 AM to 16:00 PM Eastern.
- Provided `MockCalendar` for dry-runs and automated testing environments.

### 2. Orchestrator Integration
- Hooked the calendar check into the absolute beginning of `Orchestrator.onTick()`.
- If the calendar returns `false` (market closed), the tick simply returns early, saving database queries and API calls.

### 3. Agent CLI Upgrades
- Modified `agent start --live=alpaca` to instantiate the real `USMarketCalendar`.
- Modified `agent start` (synthetic mode) to use the `MockCalendar` ensuring local evaluations and simulated weekends still execute for developer feedback.

### 4. Verification
- Added `tests/market-calendar.test.ts` to strictly verify timezone math (e.g. 09:30 ET opening, 16:00 ET closing).
- Updated `orchestrator.test.ts` with a scenario where the `MockCalendar` correctly halts execution.
