## Decisions Made
- `WashSaleLockoutOverlay` operates purely intra-proposal (MVP) and suppresses SELLs to prioritize drift-based BUYs.
- Drift targets are temporarily aliased in memory via `EvaluationState.temporaryEquivalencyMapping` to prevent the Quality Pipeline from rejecting TLH swaps.
- Execution overlays run purely synchronously within their pipeline block to guarantee sequential deterministic mutation of the `TradeProposal`.

## Issue #96 Mitigation (Red-Team Review Response)
Following the initial release-ready signal (Issue #94), a red-team review (Issue #96) highlighted several architectural and security gaps which have now been mitigated:
- **Traceability & Auditability**: Added `metadata?: Record<string, string>` to `ProposedTrade`. All generated trades are now explicitly tagged with their origin (e.g., `origin: 'DRIFT_STRATEGY'` or `origin: 'OpportunisticLossHarvestingOverlay'`) guaranteeing full lifecycle auditability in the final audit record.
- **Architectural Purity**: Execution Overlays were rewritten to be pure functions that deep-clone the incoming `TradeProposal` before mutation, resolving the heavy mutable state concern.
- **Defensive Validation**: Added strict guard checks against NaN, Infinity, zero/negative prices, and over-allocation of tax lots in the TLH generation pipeline.
- **Advanced Substitute Wash-Sale Detection**: The `WashSaleLockoutOverlay` now maps all instruments to their equivalency groups and checks for *any* BUY within the group. It explicitly suppresses *only* trades tagged with `origin: 'OpportunisticLossHarvestingOverlay'`, leaving the underlying drift trades safely intact. The emitted warning includes the suppressed instrument and value for the audit trail.
