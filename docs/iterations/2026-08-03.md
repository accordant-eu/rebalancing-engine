# Iteration Log: 2026-08-03

## Summary
Implemented the jurisdiction-agnostic Execution Overlay Pipeline for Tax-Loss Harvesting (TLH) as defined in PRD Rev 1, and resolved critical optimizer blocking bugs.

## Files Touched
- `src/optimizer/solver.ts` - Fixed event loop blocking (yields every 10ms) and added convergence failure aborts.
- `src/optimizer/index.ts` - Guarded against negative target weights.
- `src/core/overlays.ts` (NEW) - Implemented `OpportunisticLossHarvestingOverlay` (Generative) and `WashSaleLockoutOverlay` (Constraint).
- `src/core/quality.ts` - Added `temporaryEquivalencyMapping` to `EvaluationState`.
- `src/models/domain.ts` - Added `executionOverlays`, `tlhLossThresholdBps`, `equivalencyGroups` to `RebalancingPolicy`. Added `WASH_SALE_LOCKOUT` and `TLH_HARVEST_GENERATED` warnings.
- `src/core/drift.ts` - Updated `calculateDrift` to aggregate weights of substitute targets if a `temporaryEquivalencyMapping` is present.
- `src/core/trades.ts` - Wired the Execution Overlay pipeline into `generateTradeProposal`.
- `src/core/evaluation.ts` - Updated `evaluateRebalance` to dynamically instantiate configured execution overlays and pass them to trade generation.
- `tests/overlays.test.ts` (NEW) - Full unit test matrix coverage for TLH constraints and generative overrides.

## Decisions Made
- `WashSaleLockoutOverlay` operates purely intra-proposal (MVP) and suppresses SELLs to prioritize drift-based BUYs.
- Drift targets are temporarily aliased in memory via `EvaluationState.temporaryEquivalencyMapping` to prevent the Quality Pipeline from rejecting TLH swaps.
- Execution overlays run purely synchronously within their pipeline block to guarantee sequential deterministic mutation of the `TradeProposal`.
